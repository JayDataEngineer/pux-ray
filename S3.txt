❯ ### 1. "FP8 is 26 Gigs? That Is Insanely Big."                                
                                                                                
  Yes, the file size is correct. This is the most common point of confusion     
  when developers transition from the original LTX-Video to the newer LTX-2 /   
  LTX-2.3 models:                                                               
                                                                                
  *   **The Original LTX-Video** was a relatively lightweight **2 Billion       
  parameter model** [cite: 1.1.7]. Its unquantized BF16 transformer was only    
  ~4GB on disk [cite: 1.1.7], which easily fit resident in VRAM.                
  *   **LTX-2.3** is a massive, production-grade **22 Billion parameter joint   
  audio-video foundation model**.                                               
  *   **The VRAM Math:** A 22B model at 1 byte per parameter (FP8) requires     
  **22 GB of memory for the transformer alone**. When you add the surrounding   
  components (the 12B Gemma 3 text encoder [cite: 1.1.2], the audio-video VAE   
  [cite: 1.2.3], and connectors), the model takes **over 46GB in BF16**, and    
  remains **~26GB even when quantized to FP8**.                                 
                                                                                
  This is an incredibly heavy model that pushes a single 24GB RTX 4090 to its   
  absolute limits [cite: 1.2.8].

  ### 2. How Does LTX Normally Run on Consumer GPUs or `wan2gp`?                
                                                                                
  To run a 46GB model on consumer cards (like 8GB, 12GB, or 16GB GPUs), the     
  ecosystem relies on different optimization paths:                             
                                                                                
  #### A. In Standard ComfyUI (The "Shrank-to-Fit" Path)                        
  Local developers typically run LTX-2.3 using:                                 
  1.  **GGUF Quantizations:** They download `Q4_K_M` or `Q2_K` GGUFs from       
  repositories like `unsloth/LTX-2.3-GGUF`. This shrinks the model size down to 
  **11GB–18GB** so it can fit resident on 16GB cards.                           
  2.  **Sequential Component Offloading (Kijai's hooks):** They use custom      
  nodes that load the VAE, text encoder, and transformer sequentially into      
  VRAM, aggressively freeing the CPU/GPU memory caches after each component     
  executes to prevent VRAM spikes [cite: 1.2.8].                                
                                                                                
  #### B. In `wan2gp` (The `mmgp` Path)                                         
  `wan2gp` uses **`mmgp`** to handle memory [cite: 1.3.6].                      
  *   Because `mmgp` operates strictly at the Python/PyTorch layer (attaching   
  standard forward pre-hooks and post-hooks to PyTorch modules), it does not    
  compile any custom CUDA-only initialization kernels on the CPU [cite: section 
  1g].                                                                          
  *   It simply splits the unquantized 22B model into individual layer-level    
  blocks and streams them dynamically between CPU system RAM and GPU VRAM       
  *during the forward pass execution* [cite: 1.3.5].                            
  *   **The Trade-off:** While `mmgp` allows LTX-2.3 to run stable on **cards   
  as low as 6GB of VRAM** [cite: 1.3.5], the generation is slow (often taking   
  several minutes per video) because every step is bound by synchronous,        
  non-compiled PCIe transfers [cite: 1.3.4].

  1.  **The Standard SGLang FP8 Path (`convert_hf_to_fp8.py`):**

  ### Issue 1: The 18GB Text Encoder Caching Trap (Qwen-Image-Edit & LTX-2.3)   
                                                                                
  *   **The Cause:** When SGLang initializes, it briefly stages the massive     
  text encoders (Qwen2.5-VL at 16GB or Gemma 3 at 23GB) on the GPU to build the 
  execution graphs and run initial parameter checks [1.1.9, 1.2.1, 1.2.5]. It   
  then correctly offloads these weights to your CPU system RAM [1.2.1, 1.2.5].  
  *   **The Bug:** PyTorch's caching allocator **does not return this memory to 
  the NVIDIA GPU driver** [1.1.9, 1.2.1]. It keeps the 18GB of VRAM "Reserved"  
  but empty in its local pool [1.1.9]. When SGLang then attempts to allocate    
  the heavy 19GB–21GB FP8 transformer on the GPU, the CUDA driver rejects the   
  allocation because PyTorch is still hoarding that 18GB [1.1.9, 1.2.1].        
                                                                                
  #### The Proper Way to Fix It:                                                
                                                                                
  1.  **Globally Enable `expandable_segments` [cite: 64]:**                     
      Add this environment variable globally in your Docker container or before 
  launching your Ray Serve scripts:                                             
      ```bash                                                                   
      export PYTORCH_CUDA_ALLOC_CONF="expandable_segments:True"                 
      ```                                                                       
      *Why this is the gold standard:* This flag forces PyTorch's allocator to  
  dynamically release memory segments back to the GPU driver the millisecond    
  they are offloaded, completely crushing the 18GB initialization spike and     
  freeing up the VRAM for your transformer [1.1.9, 1.2.1].                      
  2.  **Force Memory Release Hooks:**                                           
      If you are running custom loading scripts, you must execute a strict      
  garbage collection and memory release cycle immediately after the text        
  encoder is offloaded and before the transformer is initialized [1.1.9,        
  1.2.1]:                                                                       
      ```python                                                                 
      import gc                                                                 
      import torch                                                              
                                                                                
      gc.collect()                                                              
      torch.cuda.empty_cache()                                                  
      ```                                                                       
  3.  **Use SGLang's Direct CPU Offload Flags Natively:**                       
      Ensure your server launch scripts strictly enforce CPU loading during     
  startup so the text encoder never sits on the GPU in the first place [1.2.1,  
  1.2.5]:                                                                       
      ```bash                                                                   
      --text-encoder-cpu-offload true --pin-cpu-memory true                     
      ```

  # LoRA Serving                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  SGLang enables the use of [LoRA adapters](https://arxiv.org/abs/2106.09685) with a base model. By incorporating techniques from [S-LoRA](https://arxiv.org/pdf/2311.03285) and [Punica](https://arxiv.org/pdf/2310.18547), SGLang can efficiently support multiple LoRA adapters for different sequences within a single batch of inputs.                                                                                                                                                                                                                                                                                                                                                                                                 
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  ## Arguments for LoRA Serving                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  The following server arguments are relevant for multi-LoRA serving:                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  * `enable_lora`: Enable LoRA support for the model. This argument is automatically set to True if `--lora-paths` is provided for backward compatibility.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  * `enable_lora_overlap_loading`: Enable asynchronous LoRA weight loading in order to overlap H2D transfers with GPU compute. This should be enabled if you find that your LoRA workloads are bottlenecked by adapter weight loading, for example when frequently loading large LoRA adapters.                                                                                                                                                                                                                                                                                                                                                                                                                                             
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  * `lora_paths`: The list of LoRA adapters to load. Each adapter must be specified in one of the following formats: \<PATH> | \<NAME>=\<PATH> | JSON with schema \{"lora\_name":str,"lora\_path":str,"pinned":bool}.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  * `max_loras_per_batch`: Maximum number of adaptors used by each batch. This argument can affect the amount of GPU memory reserved for multi-LoRA serving, so it should be set to a smaller value when memory is scarce. Defaults to be 8.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  * `max_loaded_loras`: If specified, it limits the maximum number of LoRA adapters loaded in CPU memory at a time. The value must be greater than or equal to `max-loras-per-batch`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  * `lora_eviction_policy`: LoRA adapter eviction policy when GPU memory pool is full. `lru`: Least Recently Used (default, better cache efficiency). `fifo`: First-In-First-Out.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  * `lora_backend`: The backend of running GEMM kernels for Lora modules. Currently we support Triton LoRA backend (`triton`) and Chunked SGMV backend (`csgmv`). In the future, faster backend built upon Cutlass or Cuda kernels will be added.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  * `max_lora_rank`: The maximum LoRA rank that should be supported. If not specified, it will be automatically inferred from the adapters provided in `--lora-paths`. This argument is needed when you expect to dynamically load adapters of larger LoRA rank after server startup.                                                                                                                                                                                                                                                                                                                                                                                                                                                       
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  * `lora_target_modules`: The union set of

  #### Limitations of LoRA Overlap Loading                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  However, LoRA overlap loading is not free and comes with two important caveats:                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  1. **Pinned CPU memory requirement**:                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     
     Asynchronous H2D memory copies require LoRA weights to be pinned in CPU memory, which is a finite system resource. To mitigate excessive pinned-memory usage, SGLang currently restricts `max_loaded_loras` to be at most 2× `max_loras_per_batch` when LoRA overlap loading is enabled.                                                                                                                                                                                                                                                                                                                                                                                                                                               
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  2. **Reduced multi-adapter prefill batching**:                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
     With overlap loading, adapters become available on the GPU at different times because each adapter is loaded asynchronously. This can reduce the scheduler’s ability to form multi-adapter prefill batches, since only requests whose adapters are currently loaded can be grouped together. As a result, requests for different adapters will be scheduled in separate (or smaller) prefill batches, which can increase TTFT when adapter load time is small compared to prefill compute time. This is why LoRA overlap loading is disabled by default: it should only be enabled when users have determined that LoRA weight loading is a bottleneck (EG high adapter churn, heavy adapter weights, or PCIe-bottlenecked workloads). 
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  #### Example When Overlap Loading Results in Higher Latency                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  For instance, suppose we have four LoRA adapters: `lora0`, `lora1`, `lora2`, and `lora3`. Loading any adapter takes 2ms, while the prefill step for requests for that adapter takes 20ms.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  1. **Baseline**:                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          
     The engine loads all four adapters synchronously, then runs one combined prefill batch, giving us a total time of ≈ `2 * 4 + 20 = 28ms`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  2. **With LoRA overlap loading enabled**:                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 
     The engine begins loading `lora0` and, once it is ready, schedules a prefill batch containing only `lora0` while `lora1` loads in the background. Then it schedules `lora1`’s prefill while `lora2` loads, and so on. In the worst case where prefill cannot be batched across adapters, total time is ≈ `2 + 4 * 20 = 82ms`                                                                                                                                                                                                                                                                                                                                                                                                           
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            
  In this scenario, overlap loading reduces adapter-load overhead, but the loss of multi-adapter prefill batching dominates and leads to higher TTFT.
